> **核心考点**：SFT 教模型模仿示范答案，偏好对齐教模型在多个可行答案中更倾向选择人类或产品偏好的答案。RLHF 通过奖励模型和强化学习优化，DPO 则直接用偏好对训练模型。

---

# 1. 核心问题：为什么 SFT 后还要偏好对齐

SFT 数据通常告诉模型：

```text
这个输入应该生成这个答案
```

但很多任务没有唯一标准答案。两个答案都能回答问题，但一个更好：

- 更有帮助。
- 更诚实。
- 更安全。
- 更符合产品风格。
- 更少废话。
- 更会承认不确定。

偏好对齐的数据通常是：

```text
prompt
chosen response
rejected response
```

模型学习：

```text
同一个输入下，更偏向 chosen，而不是 rejected
```

---

# 2. 偏好数据长什么样

示例：

```json
{
  "prompt": "资料没有提到退款时效，用户问退款多久到账。",
  "chosen": "资料中未提及退款到账时间，建议查询退款政策或联系人工客服确认。",
  "rejected": "退款一般 3-5 个工作日到账。"
}
```

这里 rejected 看似合理，但它使用了资料之外的常识。对于 RAG 系统，chosen 更符合忠实性要求。

偏好数据可以来自：

- 人工比较。
- 用户反馈。
- 专家审核。
- 线上 A/B。
- LLM judge 初筛后人工校准。
- 历史失败样本构造。

偏好数据的质量非常关键。如果标注标准不一致，模型会学到混乱偏好。

# 3. RLHF 的基本流程

RLHF（Reinforcement Learning from Human Feedback）典型流程：

```text
1. SFT 得到初始助手模型
2. 收集同一 prompt 下多个回答
3. 人类标注哪个更好
4. 训练 Reward Model
5. 用 PPO 等强化学习方法优化策略模型
```

Reward Model 输入 prompt 和 response，输出一个分数：

```text
RM(prompt, response) -> reward
```

PPO 优化模型，让它生成更高 reward 的回答，同时通常加入 KL 约束，避免偏离 SFT 模型太远。

直觉：

> Reward Model 学会“什么回答更受偏好”，PPO 让模型朝这个偏好方向生成。

---

# 4. RLHF 的难点

## 4.1 训练复杂

需要训练 reward model，还要做强化学习。工程复杂度、稳定性和成本都高。

## 4.2 Reward hacking

模型可能找到让 reward model 打高分但人类并不真正喜欢的模式。

例如：

- 答案变长。
- 语气过度自信。
- 用漂亮格式掩盖事实错误。
- 过度迎合用户。

## 4.3 KL 约束权衡

约束太弱，模型可能偏离原能力；约束太强，对齐效果有限。

## 4.4 标注偏差

不同标注者偏好不同。如果 rubric 不清楚，reward model 会学到噪声。

---

# 5. DPO：不用显式 Reward Model 的偏好优化

DPO（Direct Preference Optimization）直接使用偏好对训练模型，不需要单独训练 reward model 和跑 PPO。

它使用 chosen / rejected 对，让模型提高 chosen 相对于 rejected 的概率。

直觉：

```text
同一个 prompt 下：
让 chosen 更可能
让 rejected 更不可能
```

DPO 的优势：

- 训练流程简单。
- 稳定性通常更好。
- 工程成本低于 RLHF。
- 适合应用团队做偏好对齐。

局限：

- 依赖高质量偏好对。
- 对复杂长期行为优化不如完整 RL 灵活。
- 如果 SFT 模型基础差，DPO 也很难救。

---

# 6. KTO、ORPO 等方法放在哪里理解

这些方法都可以放在“偏好对齐”框架下理解。

## 6.1 KTO

KTO 不一定需要严格 chosen/rejected 成对数据，而是利用“好/坏”反馈信号优化模型偏好。

适合偏好数据不是成对比较，而是单条样本带正负标签的场景。

## 6.2 ORPO

ORPO 尝试把 SFT 和偏好优化结合在一个目标中，减少训练阶段切换。

理解重点不是背公式，而是知道：

> 这些方法都在试图让模型更偏向人类认为好的回答，同时降低 RLHF 的复杂度。

---

# 7. 偏好对齐适合优化什么

适合：

- 回答有用性。
- 拒答边界。
- 简洁和完整的平衡。
- RAG 忠实性偏好。
- 工具调用后是否正确总结。
- 安全和合规风格。
- 产品语气。

不适合单独解决：

- 缺少领域知识。
- 检索失败。
- 工具权限错误。
- 精确计算。
- 数据本身错误。

如果模型没有证据，偏好对齐只能教它更会拒答，不能凭空生成事实。

---

# 8. 偏好数据的 rubric

标注偏好前要定义规则。

例如 RAG 答案偏好：

优先级：

1. 不编造资料外事实。
2. 关键结论有引用。
3. 覆盖用户问题。
4. 表达简洁清楚。
5. 给出下一步建议。

如果没有优先级，标注者可能偏好“更好看”的错误答案，而不是“更忠实”的答案。

偏好对齐学的是标注偏好。rubric 乱，模型就乱。

---

# 9. 常见误区

## 9.1 偏好对齐能替代 SFT

通常不能。SFT 先让模型学会基本任务格式和行为，偏好对齐再细调“哪个更好”。

## 9.2 DPO 一定比 RLHF 好

不一定。DPO 工程简单、稳定，但 RLHF 在某些复杂策略优化中更灵活。选择取决于数据、成本和目标。

## 9.3 偏好对齐只做安全

不止安全。它也可以优化有用性、简洁性、引用忠实性、工具使用偏好和产品风格。

## 9.4 chosen 越长越好

如果标注偏好长答案，模型就会学会变啰嗦。rubric 要明确长度和信息密度。

# 10. 面试 Q&A

## Q1：SFT 和 RLHF 的区别是什么？

SFT 用示范答案做监督学习，教模型模仿理想输出；RLHF 用人类偏好训练 reward model，再用强化学习让模型生成更符合偏好的回答。

## Q2：DPO 为什么工程上更简单？

DPO 直接用 chosen/rejected 偏好对优化模型，不需要单独训练 reward model，也不需要 PPO 式强化学习循环，因此流程更简单稳定。

## Q3：Reward hacking 是什么？

模型找到 reward model 的漏洞，生成能拿高分但人类不真正喜欢的回答，比如过度冗长、自信但错误、格式漂亮但事实不忠实。

## Q4：偏好数据怎么保证质量？

要有清晰 rubric、标注一致性检查、人工抽检、边界样本和安全样本。偏好对齐的上限很大程度由偏好数据质量决定。
