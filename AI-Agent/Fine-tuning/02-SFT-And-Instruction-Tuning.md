> **核心考点**：SFT 用高质量输入输出样本教模型“在这种输入下应该这样回答”。它擅长学习格式、风格、任务流程和领域表达，但不保证事实正确，也不能替代 RAG 和工具。

---

# 1. 核心问题：SFT 学的是什么

SFT（Supervised Fine-Tuning）给模型一批示范：

```text
输入：用户问题 + 上下文 + 规则
目标输出：理想回答
```

训练目标是提高理想回答 token 的概率。

如果样本大量展示：

```text
用户要求退款 -> 先索要订单号 -> 说明将查询政策
```

模型之后遇到相似请求，就更倾向按这个流程回答。

SFT 学的是条件生成模式：

- 输入如何理解。
- 输出用什么格式。
- 什么语气。
- 什么步骤。
- 不知道时怎么处理。
- 工具调用参数长什么样。

---

# 2. SFT 和预训练的区别

预训练通常学习 next token prediction：

```text
给定前文，预测下一个 token
```

SFT 仍然使用类似的语言建模 loss，但数据从通用文本变成了指令样本：

```text
instruction/context -> response
```

区别在于数据分布和 loss mask。

预训练让模型学语言、知识和模式；SFT 让模型学如何作为助手响应任务。

# 3. Base model SFT vs Chat model SFT

## 3.1 Base model SFT

Base model 还没有强指令遵循能力。SFT 可以把它调成 instruction-following 模型。

要求：

- 数据量和覆盖更大。
- 需要基础安全和拒答样本。
- chat template 设计更关键。

## 3.2 Chat model 继续 SFT

Chat model 已经会对话和遵循指令。继续 SFT 通常是为了：

- 学领域风格。
- 学业务格式。
- 学工具调用风格。
- 学特定拒答边界。

风险：

- 破坏原有安全能力。
- 让模型过度拟合业务话术。
- 通用能力回退。

继续 SFT 通常需要更低学习率、更少 epoch、更强回归评估。

# 4. Chat Template：格式本身也是训练信号

聊天模型通常不是直接看到 JSON messages，而是看到模板化后的文本：

```text
<system>
你是客服助手。
</system>
<user>
退款多久到账？
</user>
<assistant>
退款通常在 3-5 个工作日到账。
</assistant>
```

不同模型模板不同。比如 role token、BOS/EOS、assistant 起始标记都可能不同。

如果训练模板和推理模板不一致，会出现：

- 模型不会停止。
- 回复格式异常。
- 多轮边界混乱。
- system 指令权重变弱。

所以微调时必须使用目标模型官方或实际部署一致的 chat template。

---

# 5. Assistant Loss：只训练该回答的部分

在多轮对话中：

```text
system：规则
user：问题
assistant：回答
tool：工具结果
assistant：最终回答
```

通常只对 assistant 消息算 loss。system、user、tool 是条件，不是模型要复现的目标。

工具调用训练时，可能对两类 assistant 输出算 loss：

1. 生成工具调用 JSON。
2. 工具结果返回后的最终回答。

要避免模型学习生成 tool 结果本身，因为工具结果应由外部系统提供。

# 6. 训练参数怎么理解

常见关键参数：

| 参数 | 影响 |
|---|---|
| learning rate | 更新幅度，过高容易破坏模型 |
| batch size | 梯度估计稳定性和显存 |
| epoch | 数据重复学习次数，过多易过拟合 |
| max sequence length | 能训练多长上下文 |
| warmup | 训练初期稳定性 |
| weight decay | 正则化 |
| gradient clipping | 防梯度爆炸 |

经验方向：

- 小数据继续 SFT：学习率低、epoch 少、强评估。
- 新任务格式学习：可适当增加样本覆盖。
- 长上下文任务：训练长度要匹配推理需求。
- 格式任务：验证 JSON/schema 成功率比 loss 更重要。

# 7. 过拟合和灾难性遗忘

## 7.1 过拟合

表现：

- 训练 loss 下降，验证表现不升反降。
- 输出越来越像训练模板。
- 面对新问法泛化差。
- 生成固定套话。

常见原因：

- 数据少。
- epoch 太多。
- 学习率太高。
- 样本重复。
- 模板过于单一。

## 7.2 灾难性遗忘

表现：

- 目标任务变好，通用能力变差。
- 安全拒答能力下降。
- 多语言能力下降。
- 原本会的工具调用格式被破坏。

缓解：

- 使用较小学习率。
- 使用 PEFT。
- 混入少量通用/安全回归数据。
- 做回归评估。
- 保留基座模型可回滚。

# 8. SFT 适合和不适合

适合：

- 固定格式抽取。
- 领域客服风格。
- 任务流程标准化。
- 工具参数格式。
- 多轮对话习惯。
- 特定写作风格。

不适合单独解决：

- 最新事实。
- 私有文档问答。
- 精确权限控制。
- 实时数据查询。
- 数学计算。
- 高风险事实判定。

这些更适合 RAG、工具和程序校验。

# 9. 常见误区

## 9.1 SFT 后就不需要 prompt

仍然需要。微调让模型更容易遵守任务模式，但当前任务、上下文、输出 schema 和安全规则仍要通过 prompt 或系统传入。

## 9.2 SFT 可以保证事实正确

不能。SFT 学的是回答模式，不是实时事实数据库。事实正确仍要靠证据、工具和评估。

## 9.3 验证 loss 低就能上线

不能。还要评估任务成功率、格式稳定、拒答、安全、通用能力回归和线上反馈。

## 9.4 训练越久越好

不一定。训练过久会过拟合和遗忘。微调应以验证集和业务指标决定停止。

# 10. 面试 Q&A

## Q1：SFT 的训练目标是什么？

SFT 通常仍是语言建模目标，但数据是指令输入和理想回答。训练时提高 assistant 目标输出 token 的概率，让模型更倾向按示范格式和行为回答。

## Q2：为什么 chat template 很重要？

因为模型实际看到的是模板化后的 token 序列。训练和推理模板不一致，会导致角色边界、停止符、多轮格式和 system 指令行为异常。

## Q3：SFT 如何避免过拟合？

使用高质量去重数据、合理验证集、较低学习率、适当 epoch、早停和回归评估。小数据场景尤其要谨慎。

## Q4：SFT 和偏好对齐有什么区别？

SFT 学“应该怎么答”的示范；偏好对齐学“多个可行回答里哪个更好”。SFT 通常先做，偏好对齐在其后改善偏好、安全和细粒度质量。
