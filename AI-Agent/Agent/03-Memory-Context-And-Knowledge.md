# 记忆、上下文与知识

Agent 经常被说成“有记忆”。但这里的记忆不是一个概念，而是一组不同层次的机制：上下文窗口、对话历史、任务状态、长期记忆、知识库、审计日志。它们解决的问题不同，不能混在一起。

记忆设计不好，Agent 会忘记目标、重复工作、引用错误事实，或者把临时猜测当成永久知识。

---

# 1. 上下文不是记忆的全部

上下文窗口是模型当前能看到的文本。它像工作台，不像数据库。

把所有历史都塞进上下文有几个问题：

- 成本越来越高。
- 无关信息干扰当前判断。
- 重要信息可能被淹没。
- 外部恶意内容可能污染指令。
- 超过窗口后仍然会丢失。

所以 Agent 需要上下文管理，而不是简单堆历史。

---

# 2. 短期记忆

短期记忆通常指当前会话中需要保留的信息，例如用户刚才说的目标、当前任务约束、已经执行的工具结果。

短期记忆适合放进 prompt，但要经过整理。长对话中可以用摘要保留主线：

```text
用户目标：
已确认事实：
已完成动作：
待解决问题：
当前限制：
```

摘要不是越短越好，而是要保留后续决策所需的信息。

---

# 3. 工作状态

工作状态是系统推进任务所需的结构化数据。

例如：

- 当前 workflow 节点。
- 子任务列表。
- 工具调用记录。
- 文件变更。
- 审批状态。
- 错误和重试次数。
- 成本和轮次预算。

工作状态应该由系统持久化，而不是只让模型在对话里记住。服务重启、任务中断、人工介入时，都依赖工作状态恢复。

---

# 4. 长期记忆

长期记忆是跨任务复用的信息，例如用户偏好、项目规范、团队术语、常用工作流、历史案例。

长期记忆写入要谨慎。不是所有信息都值得永久保存。

写入前要问：

- 这条信息是否稳定？
- 是否对未来任务有用？
- 用户是否授权？
- 是否包含敏感信息？
- 是否需要过期时间？
- 用户能否删除？

长期记忆如果没有治理，会变成一堆过期、矛盾、隐私风险很高的文本。

---

# 5. RAG 与知识库

RAG 是 Agent 获取外部知识的重要方式，但它不是长期记忆的全部。

RAG 适合：

- 私有文档问答。
- 项目知识检索。
- 政策、产品、代码库、日志资料。
- 需要引用和溯源的场景。

长期记忆更偏用户或任务历史，RAG 更偏外部知识来源。两者可以组合：Agent 先用长期记忆理解用户偏好，再用 RAG 查事实证据。

关键原则：需要事实可靠和引用时，优先使用知识库和工具，不要只靠模型记忆。

---

# 6. 上下文压缩

Agent 多步执行时，上下文会快速膨胀。压缩常见方式包括：

- 对话摘要。
- 工具结果摘要。
- 任务状态结构化。
- 只保留最近关键轮次。
- 检索相关历史。
- 把长文档交给 RAG，而不是全塞进 prompt。

压缩有风险：可能丢失证据、改变原意、遗漏限制。因此关键事实最好保留来源和原文位置。

---

# 7. 记忆冲突

不同记忆可能冲突：用户新偏好和旧偏好冲突，知识库旧版本和新版本冲突，模型参数知识和检索证据冲突。

处理冲突时要有优先级：

```text
系统规则 > 用户当前明确指令 > 权威工具/知识库 > 已确认状态 > 长期偏好 > 模型参数知识
```

如果冲突无法判断，Agent 应说明不确定性或请求人工确认，而不是强行编一个统一答案。

---

# 8. 隐私与安全

记忆系统会放大隐私风险。保存得越多，泄露面越大。

需要考虑：

- 敏感信息脱敏。
- 租户隔离。
- 访问权限。
- 数据保留期限。
- 用户删除权。
- 训练和评估数据是否复用。
- 日志是否包含隐私。

Agent 的记忆不是越强越好，而是越可控越好。
