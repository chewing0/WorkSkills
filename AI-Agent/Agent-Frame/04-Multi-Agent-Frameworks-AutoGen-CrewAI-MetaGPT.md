> **核心考点**：多 Agent 框架的价值不在于“人多力量大”，而在于把任务拆成有真实分工的角色，并用协议组织通信、交接、评审和汇总。没有清晰职责的多 Agent 只会增加成本和噪声。

---

# 1. 为什么需要多 Agent 框架

单 Agent 适合一个模型围绕目标决策。多 Agent 适合任务天然有角色分工：

- 研究员收集资料。
- 分析师整理结论。
- 工程师写代码。
- Reviewer 审查风险。
- Manager 分配任务和汇总。

多 Agent 框架提供：

- 角色定义。
- 消息传递。
- 群聊或流程。
- 任务分配。
- 代码执行环境。
- 协作终止条件。

---

# 2. 多 Agent 什么时候有价值

有价值的场景：

- 任务可拆成专业角色。
- 需要互相审查。
- 需要并行探索多个方案。
- 需要生成、评审、修改循环。
- 任务复杂到单一 prompt 难以覆盖。

不适合：

- 简单问答。
- 任务目标不清。
- 角色职责重叠。
- 对延迟和成本极敏感。
- 缺少评估和停止条件。

多 Agent 会显著增加 token、延迟和不确定性。

# 3. AutoGen：对话式多 Agent

AutoGen 的核心是 ConversableAgent：

```text
Agent A <-> Agent B <-> UserProxyAgent
```

特点：

- Agent 之间通过消息对话协作。
- 可以有人类代理或代码执行代理。
- 适合研究、代码、对话协作实验。
- GroupChat 支持多个 Agent 群聊。

优势：

- 灵活。
- 适合探索型任务。
- 对多角色对话建模自然。

风险：

- 对话可能发散。
- 成本高。
- 停止条件难。
- 生产可控性需要额外设计。

# 4. CrewAI：角色和任务流程

CrewAI 更强调：

- Agent role。
- Task。
- Process。
- Tool。

常见流程：

```text
定义角色 -> 定义任务 -> 指定流程 -> 执行 crew
```

Process 可以是：

- Sequential。
- Hierarchical。

适合：

- 内容生产。
- 调研报告。
- 多角色流程原型。
- 任务分工较清楚的场景。

风险：

- 角色描述容易流于表面。
- 如果任务边界不清，输出会互相重复。
- 生产状态和权限控制仍要补充。

# 5. MetaGPT：SOP 式多 Agent

MetaGPT 的核心思想是把软件公司协作流程抽象成 SOP：

```text
Product Manager -> Architect -> Engineer -> QA
```

它强调：

- 标准流程。
- 角色产物。
- 文档交接。
- 软件开发任务。

适合理解“多 Agent 如何按组织流程协作”。

但实际工程中要注意：

- 生成代码不等于可维护代码。
- SOP 过重时成本高。
- 真实仓库上下文和测试仍很关键。
- 角色产物要能被验证。

# 6. 多 Agent 的核心难点

## 6.1 通信成本

每个 Agent 都要读写消息，token 成本快速上升。

## 6.2 角色重叠

角色职责不清时，多个 Agent 会重复做同一件事。

## 6.3 冲突解决

Agent 之间意见不同，需要规则：

- 谁裁决？
- 是否投票？
- 是否交给 Reviewer？
- 是否请求用户？

## 6.4 停止条件

群聊容易继续讨论。必须定义完成标准和最大轮数。

## 6.5 评估困难

要评估每个角色贡献、通信质量、最终结果和成本。

# 7. 设计多 Agent 的原则

```text
先拆任务，再设角色；
先定义产物，再定义对话；
先设停止条件，再让它协作；
先能评估，再扩大角色数量。
```

每个角色都应有：

- 输入。
- 输出。
- 工具权限。
- 成功标准。
- 交接对象。

没有明确产物的角色，很容易变成“聊天装饰”。

# 8. 常见误区

## 8.1 多 Agent 一定比单 Agent 强

不一定。没有真实分工时，多 Agent 只是增加成本和不确定性。

## 8.2 给角色起名就完成分工

不够。角色要有职责、输入输出、工具权限和评价标准。

## 8.3 群聊越开放越智能

开放群聊容易发散。生产任务需要流程、轮数和终止条件。

## 8.4 Reviewer Agent 能保证质量

不能保证。Reviewer 也会错。关键结果仍要工具测试、规则校验或人工审核。

# 9. 面试 Q&A

## Q1：什么时候应该用多 Agent？

当任务有真实角色分工、需要互相审查、并行探索或多阶段交接时。简单任务不应为了概念而上多 Agent。

## Q2：AutoGen 和 CrewAI 的差异是什么？

AutoGen 更偏对话式多 Agent 协作和群聊；CrewAI 更偏角色、任务和流程组织。前者灵活，后者流程感更强。

## Q3：多 Agent 最大风险是什么？

成本和不可控性。包括对话发散、角色重复、冲突无裁决、停止条件不清和评估困难。

## Q4：如何让多 Agent 更可靠？

明确角色职责、输入输出、工具权限、交接产物、最大轮数、裁决规则和评估指标。
