> **核心考点**：Agent 框架选型不是比较谁更流行，而是看任务是否需要状态、工具、图、多人协作、低代码运营、可观测性和生产恢复。越接近生产，越要关注可控性和可迁移性。

---

# 1. 选型先看任务复杂度

可以按复杂度分层：

| 复杂度 | 任务形态 | 倾向 |
|---|---|---|
| L1 | 单轮问答、简单分类 | 手写 prompt + model |
| L2 | RAG 问答 | RAG 框架或轻量 LangChain/LlamaIndex |
| L3 | 多步工具调用 | LangGraph / workflow |
| L4 | 高风险业务流程 | 状态机 + 权限 + HITL |
| L5 | 多角色协作 | AutoGen/CrewAI/MetaGPT |
| L6 | 快速业务搭建 | Dify/Coze/Flowise |

不要一开始就上 L5/L6。先确认问题真的需要这些复杂度。

# 2. 生产能力清单

框架上线前要检查：

- 模型版本可控。
- Prompt 版本可控。
- 工具权限可控。
- 状态可持久化。
- 支持 checkpoint。
- 支持 trace。
- 支持评估回放。
- 支持超时和重试。
- 支持人工确认。
- 支持灰度和回滚。
- 能导出日志。
- 能和现有鉴权、数据库、监控集成。

很多框架 demo 很快，但生产能力需要自己补。

# 3. 框架锁定风险

锁定来源：

- Prompt 模板格式。
- Tool schema 格式。
- Memory 存储格式。
- State 定义方式。
- Callback/trace 格式。
- Workflow 配置格式。
- 平台专有插件。

降低锁定：

- 业务逻辑和框架代码分层。
- 工具定义尽量标准 JSON Schema。
- 状态使用自己的数据模型。
- Prompt 独立版本管理。
- 评估集独立于框架。
- 关键工具通过后端 API 暴露。

---

# 4. 从原型到生产的路线

```text
原型：
  快速验证模型和流程

试点：
  加入日志、评估集、基础权限

生产：
  显式状态、灰度、回滚、审计、监控

规模化：
  多租户、成本控制、SLA、运维和数据闭环
```

不要把原型代码直接当生产系统。

原型阶段可以重速度；生产阶段必须重可恢复和可观测。

# 5. 迁移策略

框架迁移常见原因：

- 原框架状态能力不够。
- 性能瓶颈。
- 版本变动太快。
- 平台锁定。
- 需要更强生产控制。

迁移前先抽离：

- Prompt。
- Tool schema。
- State schema。
- 评估集。
- 业务 API。
- trace 格式。

如果这些都绑死在框架里，迁移成本会很高。

---

# 6. 手写 workflow vs 使用框架

手写 workflow 优点：

- 可控。
- 少依赖。
- 易调试。
- 易和业务系统深度集成。

缺点：

- 重复造轮子。
- 生态集成少。
- 需要自己做观测和评估。

框架优点：

- 快。
- 组件多。
- 社区生态。
- 标准化抽象。

缺点：

- 抽象成本。
- 版本风险。
- 黑盒调试。
- lock-in。

选择不是二选一。常见做法是：核心业务 workflow 手写，LLM/RAG/工具组件使用框架。

---

# 7. 评估框架效果

不要只比较开发速度，还要比较：

- 任务成功率。
- 工具调用准确率。
- trace 完整度。
- 调试时间。
- 失败恢复能力。
- 延迟和成本。
- 团队学习成本。
- 迁移成本。
- 与现有系统集成难度。

一个框架让 demo 快 3 天，但让生产调试慢 3 个月，就不一定值得。

# 8. 常见误区

## 8.1 选最火框架就对

不一定。框架适配任务和团队比热度更重要。

## 8.2 先用框架，之后再治理

如果早期没有状态、工具和评估边界，后面治理会很痛苦。

## 8.3 自研一定更稳

不一定。自研也要维护模型接入、工具、trace、评估和部署。不要低估成本。

## 8.4 低代码和代码框架互斥

不互斥。低代码可以做业务配置层，核心工具和状态由代码服务控制。

# 9. 面试 Q&A

## Q1：如何选择 LangChain、LangGraph、AutoGen、CrewAI？

简单链路和 RAG 原型用 LangChain；复杂有状态、多分支、可恢复 Agent 用 LangGraph；对话式多 Agent 协作用 AutoGen；角色任务流程型多 Agent 可看 CrewAI。

## Q2：生产 Agent 框架必须具备哪些能力？

状态持久化、trace、工具权限、错误恢复、人工确认、评估回放、版本管理、灰度回滚和监控。

## Q3：如何避免框架锁定？

把 Prompt、Tool schema、State schema、评估集和业务 API 从框架中抽离，使用标准数据结构和独立版本管理。

## Q4：什么时候手写 workflow 更好？

高风险业务流程、强事务、权限复杂、状态明确且需要深度集成现有系统时，手写 workflow 或状态机通常更稳。
