> **核心考点**：Agent 的记忆不是把所有历史都塞进上下文。可靠记忆要区分当前任务状态、对话历史、长期知识、用户偏好和工具结果，并决定何时写入、如何检索、何时遗忘。

---

# 1. 核心问题：Agent 为什么需要记忆

多步任务中，模型必须知道：

- 用户最初目标。
- 已经做过哪些步骤。
- 工具返回了什么。
- 还有哪些待办。
- 用户偏好和约束是什么。
- 哪些信息可以长期复用。

如果没有记忆，Agent 会：

- 重复问同样问题。
- 忘记已完成步骤。
- 覆盖用户约束。
- 把旧工具结果当新结果。
- 多轮对话状态混乱。

但记忆不是越多越好。上下文越长，成本越高，噪声越多，也越容易冲突。

---

# 2. 四类常见记忆

| 类型 | 解决的问题 | 典型存储 |
|---|---|---|
| 短期记忆 | 当前对话最近内容 | 上下文窗口 |
| 工作状态 | 当前任务进度和中间结果 | state/checkpoint |
| 长期记忆 | 可跨会话复用的信息 | 数据库、向量库 |
| 外部知识 | 文档、政策、代码、工单 | RAG/搜索工具 |

不要把它们混成一个“memory”。不同记忆有不同生命周期和权限。

---

# 3. 短期记忆：上下文窗口不是长期记忆

短期记忆通常就是当前 prompt 里的消息历史和工具结果。

优点：

- 模型直接可见。
- 使用简单。

缺点：

- 受上下文窗口限制。
- 成本随长度增加。
- 无关历史会干扰模型。
- 窗口外内容不会自动保留。

因此多轮 Agent 不应无脑保留全量历史，而应保留：

- 当前目标。
- 最近关键交互。
- 已完成步骤。
- 待办。
- 关键工具结果。
- 用户明确约束。

---

# 4. 工作状态：比聊天历史更重要

工作状态是结构化任务进度。

例如：

```json
{
  "goal": "修复测试失败",
  "current_step": "run_related_tests",
  "completed_steps": ["read_logs", "inspect_code", "apply_patch"],
  "open_questions": [],
  "files_changed": ["src/a.py"],
  "last_test_result": "failed: test_x"
}
```

工作状态比自然语言历史更可靠，因为它：

- 可读写。
- 可 checkpoint。
- 可恢复。
- 可审计。
- 可被程序校验。

复杂 Agent 应优先维护结构化 state，而不是只依赖对话 transcript。

---

# 5. 长期记忆：什么时候该写入

长期记忆适合保存跨会话有价值的信息：

- 用户偏好。
- 项目长期约束。
- 常用工具配置。
- 已确认的业务规则。
- 历史任务总结。

但不能随便写。写入前要判断：

```text
这条信息是否长期有效？
是否经过用户确认？
是否包含敏感信息？
是否有过期时间？
是否会影响未来决策？
```

错误长期记忆很危险。它会让 Agent 在未来任务中持续带偏。

---

# 6. 记忆检索：不是存了就有用

长期记忆通常要检索回来才能用。

常见方式：

- 关键词查询。
- 向量检索。
- 按用户或项目过滤。
- 按时间和类型过滤。
- 最近使用排序。

检索回来后还要判断：

- 是否和当前任务相关。
- 是否过期。
- 是否和当前用户输入冲突。
- 是否有权限使用。

记忆检索本质上是小型 RAG，需要同样关注召回、排序、权限和引用。

---

# 7. 摘要记忆

长对话可以压缩成摘要：

```text
用户希望使用中文回答；当前任务是修复登录模块测试；
已确认问题来自 token 过期逻辑；已修改 auth.py；
下一步需要运行 login 相关测试。
```

摘要优点：

- 节省上下文。
- 保留任务主线。

风险：

- 摘要可能遗漏细节。
- 摘要可能误解原话。
- 旧摘要可能和新状态冲突。

因此摘要最好结构化，并在关键任务中保留原始证据链接或工具结果。

---

# 8. 实体记忆和偏好记忆

实体记忆保存人、项目、系统、工具等实体信息。

例如：

```text
项目 WorkSkills 是 Obsidian 知识库。
用户偏好：文档要讲透，不要概念罗列。
```

偏好记忆要谨慎：

- 用户临时要求不应永久保存。
- 敏感偏好不应保存。
- 过时偏好应可更新。
- 重要偏好最好显式确认。

# 9. 常见误区

## 9.1 全量历史就是最好记忆

不对。全量历史成本高、噪声大、容易冲突。更好的做法是结构化状态 + 必要摘要 + 可检索原始记录。

## 9.2 向量库记忆等于长期记忆

向量库只是存取方式。长期记忆还需要写入策略、权限、过期、更新和删除。

## 9.3 模型自己会记住

不会。上下文窗口外的信息不会自动保留。跨会话记忆必须由系统存储和检索。

## 9.4 记忆越个性化越好

不一定。个性化需要隐私、权限和用户控制。错误个性化会持续误导模型。

# 10. 面试 Q&A

## Q1：Agent 的 memory 和 RAG 有什么区别？

RAG 通常检索外部知识库，memory 更偏任务状态、用户偏好和历史经验。但长期记忆常用 RAG 技术实现，两者边界在用途而不是技术。

## Q2：为什么复杂 Agent 需要结构化 state？

结构化 state 可恢复、可审计、可校验，比纯聊天历史更稳定。它能记录目标、步骤、工具结果、待办和错误。

## Q3：长期记忆写入要注意什么？

要确认长期有效、与未来任务相关、用户允许、无敏感泄露，并有更新和删除机制。

## Q4：如何避免上下文越来越长？

保留关键状态，摘要长历史，检索必要记忆，丢弃无关内容，并对工具结果做压缩和引用。
