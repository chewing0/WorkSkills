> **核心考点**：Action 是 Agent 从“建议”走向“改变外部世界”的环节。只要涉及写入、删除、发送、支付、执行代码，就必须有权限、沙箱、确认、幂等和审计。

---

# 1. 核心问题：行动为什么比回答危险

模型回答错了，可以撤回或修正；行动错了，可能已经改变系统状态。

高风险行动包括：

- 删除文件。
- 修改数据库。
- 发起退款。
- 发送邮件。
- 调用生产 API。
- 执行代码。
- 发布内容。
- 修改权限。

所以 Agent Action 不是“模型说要做就做”，而是受控执行。

---

# 2. Action 的基本链路

```text
模型生成行动意图
  │
  ├─► 系统校验参数
  ├─► 检查权限和风险等级
  ├─► 必要时请求人工确认
  ├─► 在受控环境执行
  ├─► 记录审计日志
  ├─► 返回执行结果
  └─► 更新状态或回滚
```

这条链路里，模型只负责提出意图。系统负责控制能不能做。

---

# 3. 读操作和写操作要分级

读操作：

- 查询订单。
- 检索文档。
- 读取文件。
- 获取日志。

写操作：

- 修改订单。
- 写文件。
- 删除数据。
- 发消息。
- 执行部署。

读操作也可能敏感，但写操作风险更高。设计工具时要分开：

```text
query_order
create_refund_request
confirm_refund
```

不要用一个万能工具同时读写。

---

# 4. 幂等性

幂等是指同一个操作执行多次，结果不会重复造成副作用。

例如：

```text
使用 idempotency_key 发起退款
同一个 key 重复提交不会重复退款
```

Agent 可能因为超时、重试或状态不清重复调用工具。高风险动作必须设计幂等。

没有幂等，Agent 重试可能造成重复扣款、重复发信、重复创建工单。

---

# 5. 人工确认

需要人工确认的情况：

- 不可逆操作。
- 金额相关操作。
- 外部发送消息。
- 删除或覆盖数据。
- 权限变更。
- 用户意图不明确。
- 模型置信度不足。

确认内容要具体：

```text
将为订单 A12345 发起退款，金额 128 元，原因：7 天无理由。
是否确认？
```

不要只问：

```text
是否继续？
```

用户需要知道继续会发生什么。

---

# 6. 沙箱和隔离

代码执行、文件操作和网页自动化应在沙箱中进行。

沙箱要限制：

- 文件系统访问范围。
- 网络访问。
- 环境变量。
- 系统命令。
- CPU/内存/时间。
- 外部凭证。

原则：

> Agent 只拿完成任务所需的最小权限。

如果必须访问生产系统，应通过受控 API，而不是让模型直接操作 shell 或数据库。

---

# 7. 回滚和补偿

不是所有操作都能真正回滚。需要区分：

- 可回滚：数据库事务、草稿修改。
- 可补偿：发错消息后追加说明，创建退款撤销单。
- 不可逆：删除外部数据、发送敏感邮件、支付转账。

对不可逆操作，需要更强确认和权限。

Agent 工作流要记录：

- 执行前状态。
- 执行参数。
- 执行结果。
- 回滚或补偿方式。

---

# 8. 审计日志

审计至少记录：

- 谁发起。
- 何时发起。
- 模型建议了什么。
- 实际执行了什么工具。
- 参数是什么。
- 权限检查结果。
- 是否人工确认。
- 工具返回结果。
- 失败和重试。

审计不是只为合规，也用于复盘 Agent 失败。

# 9. 常见误区

## 9.1 模型确认了就算授权

不算。授权来自用户身份、系统权限和明确确认，不来自模型判断。

## 9.2 只要工具参数正确就能执行

不够。还要检查权限、风险、状态、幂等和业务规则。

## 9.3 沙箱会影响效率，可以后补

高风险执行能力一旦上线，安全边界必须先有。后补很容易留下事故窗口。

## 9.4 失败重试越多越稳

不一定。重复写操作可能放大事故。重试要有限，并且依赖幂等。

# 10. 面试 Q&A

## Q1：Agent Action 为什么要分读写权限？

读操作主要风险是信息泄露，写操作会改变外部状态。写操作需要更严格的权限、确认、幂等和审计。

## Q2：幂等性为什么重要？

Agent 可能因超时或状态不清重复调用工具。幂等能避免重复执行造成重复扣款、重复发信或重复创建资源。

## Q3：代码执行 Agent 如何保证安全？

在沙箱中执行，限制文件、网络、环境变量和资源，避免生产凭证暴露，并记录执行日志。

## Q4：高风险动作怎么设计确认？

确认信息要包含对象、动作、金额或影响范围、原因和后果，让用户或审批系统明确知道确认的内容。
