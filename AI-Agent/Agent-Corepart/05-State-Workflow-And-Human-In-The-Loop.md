> **核心考点**：生产 Agent 不能只依赖一段对话历史。它需要显式状态、可恢复 checkpoint、受控工作流和人工确认点，才能处理长任务、失败恢复和高风险操作。

---

# 1. 核心问题：为什么需要状态管理

Agent 多步执行时必须知道：

- 当前处于哪个阶段。
- 已完成什么。
- 下一个动作是什么。
- 哪些工具结果有效。
- 哪些用户确认已经获得。
- 哪些错误需要恢复。

如果状态只藏在对话历史里，系统很难恢复、审计和控制。

显式 state 是生产 Agent 的骨架。

---

# 2. State 应该存什么

典型 state：

```json
{
  "task_id": "T123",
  "goal": "处理退款请求",
  "stage": "awaiting_user_confirmation",
  "user_id": "U1",
  "order_id": "A12345",
  "tool_results": {
    "order_status": "delivered",
    "refund_quote": 128
  },
  "pending_action": "confirm_refund",
  "confirmed": false,
  "attempts": 1
}
```

State 不应该只是一段自然语言摘要。关键字段要结构化，便于程序判断和权限控制。

---

# 3. Checkpoint 和恢复

长任务可能中断：

- 模型调用失败。
- 工具超时。
- 服务重启。
- 用户稍后回复。
- 人工审批等待。

Checkpoint 让系统能从某个状态恢复。

需要保存：

- 当前 state。
- 已执行 action。
- 工具结果。
- 计划。
- 消息历史摘要。
- 待确认动作。

恢复时要避免重复执行高风险动作，因此 action 记录和幂等 key 很重要。

---

# 4. 状态机式 Agent

状态机把流程限制在明确状态之间：

```text
collect_info
  -> query_order
  -> quote_refund
  -> await_confirmation
  -> execute_refund
  -> done
```

优点：

- 可控。
- 可审计。
- 容易测试。
- 适合高风险业务。

缺点：

- 灵活性较低。
- 状态设计需要前期建模。

常见做法是让模型在状态内做语言理解和参数提取，而状态转移由程序控制。

---

# 5. Workflow 和 Agent 的分工

Workflow 负责：

- 固定流程。
- 状态转移。
- 权限检查。
- 人工确认。
- 重试策略。
- 审计日志。

Agent 负责：

- 理解自然语言。
- 补全缺失信息。
- 选择合适工具。
- 总结工具结果。
- 处理模糊情况。

这个分工能避免模型越权控制关键流程。

---

# 6. Human-in-the-Loop

人工介入不是失败，而是可靠系统的一部分。

需要人工的情况：

- 用户意图不清。
- 工具结果冲突。
- 高风险动作。
- 模型置信度低。
- 安全策略触发。
- 超过自动化边界。

人工介入可以是：

- 用户确认。
- 专家审核。
- 管理员审批。
- 人工接管对话。
- 事后抽检。

设计重点是把需要人工判断的信息整理清楚，而不是把完整混乱 trace 扔给人。

---

# 7. 多轮和异步任务

Agent 任务可能跨越时间：

```text
今天提交申请
明天审批返回
后天继续执行
```

这要求：

- state 持久化。
- 用户会话和任务分离。
- 支持异步回调。
- 支持超时和过期。
- 支持提醒和重新进入流程。

不要把“对话窗口还在”当作任务状态。

---

# 8. 常见误区

## 8.1 对话历史就是状态

不够。对话历史难以程序判断，也难以恢复和审计。关键状态应结构化。

## 8.2 Agent 可以自己决定所有状态转移

高风险业务不应如此。状态转移应由工作流规则控制，模型提供建议或参数。

## 8.3 人工介入降低智能程度

不对。人工介入提高系统可靠性，尤其在高风险和模糊边界场景。

## 8.4 Checkpoint 只用于训练

Agent 执行也需要 checkpoint，用于任务恢复、审计和防重复执行。

# 9. 面试 Q&A

## Q1：为什么生产 Agent 需要显式 state？

显式 state 支持恢复、审计、权限检查和流程控制。仅靠对话历史容易丢状态、重复动作和难以测试。

## Q2：状态机和自由 Agent 有什么取舍？

状态机可控、稳定、可测试，适合生产流程；自由 Agent 灵活，但风险高。实际系统常在状态机内嵌入模型决策。

## Q3：Human-in-the-Loop 应该放在哪里？

放在高风险动作、信息不足、工具冲突、模型低置信度和策略边界处。人工确认要展示具体行动和影响。

## Q4：异步 Agent 任务要注意什么？

要持久化任务状态，处理回调、超时、过期、用户重新进入和重复执行问题。
