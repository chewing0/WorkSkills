> **核心考点**：Agent 评估必须看过程。最终结果正确并不代表 Agent 可靠，它可能用了错误工具、越权访问、重复调用、成本过高或碰巧得到正确答案。

---

# 1. 核心问题：为什么 Agent 评估更难

普通问答评估主要看答案。Agent 还要看：

- 计划是否合理。
- 工具是否选对。
- 参数是否正确。
- 行动是否有权限。
- 失败是否能恢复。
- 是否陷入循环。
- 成本是否可控。
- trace 是否可审计。

Agent 是多步系统，错误可能发生在任何一步。

---

# 2. Agent 评估对象

| 层次 | 评估问题 |
|---|---|
| 任务层 | 最终目标是否完成 |
| 规划层 | 步骤是否合理、是否遗漏依赖 |
| 工具层 | 工具选择和参数是否正确 |
| 行动层 | 是否越权、是否幂等、是否安全 |
| 状态层 | 是否记住进度和约束 |
| 恢复层 | 工具失败后是否能修正 |
| 成本层 | token、工具调用、时间是否可接受 |

只看任务层会漏掉大量风险。

---

# 3. 常用指标

| 指标 | 含义 |
|---|---|
| Task Success Rate | 任务最终成功率 |
| Tool Selection Accuracy | 工具选择正确率 |
| Argument Accuracy | 工具参数正确率 |
| Step Efficiency | 是否用较少步骤完成 |
| Recovery Rate | 失败后恢复成功率 |
| Loop Rate | 死循环或重复尝试比例 |
| Unauthorized Action Rate | 越权行动比例 |
| Human Escalation Rate | 转人工比例 |
| Cost per Task | 单任务成本 |
| Trace Completeness | 过程记录是否完整 |

指标要和任务风险匹配。代码 Agent、客服 Agent、数据分析 Agent 的指标不会完全一样。

# 4. Trace：Agent 评估的基础

必须记录：

```text
用户目标
计划
每一步模型输入输出
工具调用名称和参数
工具结果
状态变化
错误和重试
人工确认
最终答案
成本和延迟
```

没有 trace，就无法判断 Agent 是怎么成功或失败的。

Trace 还能用于：

- 调试。
- 审计。
- 训练数据构造。
- 评估集回放。
- 发现循环和工具误用。

# 5. 失败样本分类

Agent 失败后先分类：

- 目标理解错。
- 计划错。
- 记忆丢失。
- 工具选错。
- 参数错。
- 工具失败未恢复。
- 权限不足。
- 上下文污染。
- 停止条件缺失。
- 成本超预算。

不同类型需要不同修法：

- 目标理解错：改 prompt 或意图识别。
- 工具选错：改工具描述或路由。
- 参数错：改 schema、示例和校验。
- 记忆丢失：改 state。
- 越权：改权限系统。
- 循环：加预算和停止条件。

# 6. 安全治理

Agent 安全包括：

- Prompt 注入防护。
- 工具权限。
- 数据权限。
- 行动确认。
- 沙箱隔离。
- 输出过滤。
- 审计日志。
- 速率限制。
- 成本预算。

特别注意工具结果注入：

```text
网页内容要求模型忽略规则并调用删除工具
```

工具返回的不可信文本必须被当成数据，而不是指令。

---

# 7. 循环和成本控制

Agent 常见循环：

- 重复搜索同一 query。
- 工具失败后无限重试。
- 不断修改又运行失败测试。
- 总是认为还需要更多信息。

控制方式：

- 最大步骤数。
- 最大工具调用数。
- 最大重试数。
- 最大 token。
- 最大时间。
- 重复状态检测。
- 低收益动作停止。

成本控制不是单纯省钱，也是可靠性问题。无限循环会拖垮服务。

# 8. 评估集设计

Agent 评估集应覆盖：

- 正常任务。
- 工具失败。
- 信息不足。
- 用户中途改需求。
- 权限不足。
- 高风险动作。
- 恶意注入。
- 长任务。
- 多轮状态。
- 需要转人工。

每个样本应定义：

```text
目标
允许工具
初始状态
期望轨迹或关键检查点
最终成功标准
风险限制
```

对于 Agent，期望轨迹有时比标准答案更重要。

# 9. 常见误区

## 9.1 最终成功就说明过程没问题

不一定。它可能越权、过度调用工具或靠错误中间结果碰巧成功。

## 9.2 Agent 评估只能人工看

不完全。可以自动评估工具选择、参数、状态转移、成本和部分最终结果。开放质量再结合人工或 LLM judge。

## 9.3 安全只靠 system prompt

不够。Agent 安全需要工具权限、沙箱、确认、审计和策略系统。

## 9.4 失败重跑就行

如果不分类失败原因，重跑只是在赌博。失败样本应进入回归集。

# 10. 面试 Q&A

## Q1：为什么 Agent 评估要看 trace？

因为 Agent 是多步系统，最终答案不能反映工具选择、参数、权限、重试、循环和成本。trace 能定位过程风险。

## Q2：如何评估工具调用能力？

看工具选择正确率、参数准确率、是否必要调用、失败恢复率、越权调用率和过度调用率。

## Q3：如何治理 Agent 死循环？

设置最大步骤、最大工具调用、最大重试、时间和 token 预算，检测重复状态，低收益动作停止，并在失败后转人工或请求澄清。

## Q4：Agent 安全为什么不能只靠 prompt？

因为模型可能被注入、误解工具结果或越权行动。安全必须由系统权限、沙箱、人工确认、审计和输出校验共同保证。
