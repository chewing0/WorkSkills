# 状态持久化、Checkpoint 与恢复

Agent 是多步系统。只保存用户消息和最终回答，无法支撑长任务、工具调用、人工审批、失败恢复和审计。生产 Agent 必须把状态从“模型上下文”中抽出来，变成系统可管理的数据。

可以记住一句话：上下文是给模型看的，状态是给系统控制流程用的。

---

# 1. 状态的类型

Agent 系统里常见状态包括：

| 状态类型 | 例子 | 作用 |
|---|---|---|
| 会话状态 | 用户 ID、会话 ID、历史摘要、偏好 | 维持交互连续性 |
| 任务状态 | task_id、阶段、进度、阻塞原因 | 支持异步、恢复和查询 |
| 工作流状态 | 当前节点、分支、等待条件 | 支持复杂流程编排 |
| 工具状态 | 调用参数、结果、错误、耗时 | 支持重试、审计和质量分析 |
| 记忆状态 | 长期偏好、项目知识、已确认事实 | 支持跨任务复用 |
| 审计状态 | 权限判断、人工审批、关键动作 | 支持安全和合规 |

这些状态不一定存在同一个数据库里，但要能通过 task_id、session_id、trace_id 关联起来。

---

# 2. 为什么不能只存聊天历史

聊天历史是面向语言交互的，不是面向工程恢复的。

只存聊天历史会带来几个问题：

- 很难知道任务执行到哪一步。
- 很难判断哪些事实已确认，哪些只是模型猜测。
- 工具结果容易被长文本淹没。
- 服务重启后无法准确恢复未完成任务。
- 审计时难以区分用户输入、模型输出、工具结果和系统决策。

更好的方式是：聊天历史可以保存，但关键状态要结构化。例如任务列表、工具调用记录、证据表、风险清单、审批记录、文件变更列表。

---

# 3. Checkpoint

Checkpoint 是可恢复的执行快照。

一个 checkpoint 可以包含：

```text
checkpoint
  ├─ task_id
  ├─ workflow_node
  ├─ agent_state
  ├─ relevant_context_summary
  ├─ tool_results
  ├─ pending_actions
  ├─ budgets
  ├─ created_at
  └─ version
```

Checkpoint 的价值在于，任务中断后不必从头执行。对于长任务、多 Agent、人工审批和外部回调，checkpoint 几乎是必需的。

需要注意，checkpoint 不应该保存无法复现的隐式状态。比如只保存“模型刚才想继续下一步”没有意义；应该保存明确的节点、输入、输出和待执行动作。

---

# 4. 恢复策略

恢复不是简单地“重新跑一遍”。不同失败需要不同策略。

常见恢复方式：

- 从最近 checkpoint 继续。
- 重试失败工具调用。
- 跳过非关键分支。
- 回滚已执行动作。
- 请求人工输入。
- 标记任务失败并保留部分结果。

恢复前要判断动作是否幂等。读操作通常可以重试，写操作要谨慎。比如重复发送邮件、重复退款、重复提交订单都是严重问题。

因此工具调用应尽量带幂等键，外部动作应记录执行结果。恢复时先检查动作是否已经成功，再决定是否重试。

---

# 5. 状态存储选型

不同状态适合不同存储。

- Redis：适合短期会话、缓存、分布式锁、队列辅助。
- 关系数据库：适合任务状态、审计记录、权限和业务关联。
- 对象存储：适合文件、长日志、模型输出产物。
- 向量数据库：适合长期语义记忆和知识检索。
- 日志系统：适合完整 trace 和事件流。

不要把所有东西都塞进向量库。向量库适合语义检索，不适合做权威任务状态、事务和审计。

也不要把所有状态都塞进 Redis。Redis 快，但如果没有持久化策略和数据模型，长期审计和恢复会困难。

---

# 6. 状态版本与并发

Agent 运行过程中，多个节点或多个 Worker 可能同时更新状态。尤其在多 Agent 和异步任务里，并发写入很常见。

需要考虑：

- 状态版本号，避免旧结果覆盖新结果。
- 乐观锁或悲观锁。
- 资源级锁，例如文件、订单、任务节点。
- 状态变更事件，便于追踪。
- 幂等更新，避免重复回调重复写入。

状态更新最好由系统代码完成，而不是让模型直接写数据库。模型可以建议更新内容，系统负责校验、合并和持久化。

---

# 7. 长期记忆与合规

长期记忆能提升个性化和跨任务连续性，但也带来隐私和合规问题。

长期记忆写入前要问：

- 这条信息是否真的值得长期保存？
- 用户是否授权？
- 是否包含敏感信息？
- 是否有过期时间？
- 用户能否查看、修改或删除？
- 后续检索时是否可能越权暴露？

很多场景不需要长期记忆，只需要当前任务状态和短期会话摘要。长期记忆越多，越要重视治理。
