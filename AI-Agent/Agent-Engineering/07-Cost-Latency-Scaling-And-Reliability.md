# 成本、延迟、扩缩容与可靠性

Agent 系统的成本和延迟通常不是线性增长。一个用户请求可能触发多次模型调用、多次检索、多次工具调用和多轮自我修正。功能越智能，越需要工程手段控制预算和可靠性。

如果没有成本、延迟和失败治理，Agent 很容易从“聪明”变成“昂贵且不稳定”。

---

# 1. 成本从哪里来

Agent 成本主要来自：

- 模型输入 token。
- 模型输出 token。
- embedding 和 reranking。
- 工具调用和外部 API。
- 自托管模型的 GPU 资源。
- 队列、存储、日志和 trace。
- 人工审批和运营成本。

其中最容易被低估的是“多轮放大”。一个请求如果需要 6 次模型调用，每次都带很长上下文，成本会远高于普通聊天。

成本治理要按任务链路看，而不是只看单次模型调用价格。

---

# 2. Token 预算

Token 预算是 Agent 的刹车。

可以设置：

- 单次模型调用最大输入长度。
- 单次模型调用最大输出长度。
- 单个任务最大总 token。
- 单个用户或租户每日预算。
- 每类工具或流程的最大调用次数。
- 超预算后的降级策略。

预算不是为了粗暴截断，而是为了迫使系统做选择：哪些上下文真正必要，哪些工具结果可以摘要，哪些任务需要异步，哪些情况应该请求用户补充而不是继续猜。

预算信息也应该进入 prompt 或状态，让 Agent 知道自己需要简洁、分阶段或停止。

---

# 3. 缓存策略

缓存能显著降低成本和延迟，但要小心缓存错误结果。

常见缓存：

- Prompt cache：相同前缀或系统上下文复用。
- Semantic cache：相似问题复用答案或中间结果。
- RAG cache：缓存检索结果和 rerank 结果。
- Tool cache：缓存只读工具调用结果。
- Embedding cache：避免重复向量化。
- Evaluation cache：离线评估中复用模型输出。

缓存适合稳定、只读、低风险内容。不适合个性化强、权限敏感、实时性强或高风险决策。

缓存键要包含影响结果的因素，例如用户权限、知识库版本、prompt 版本、模型版本和时间范围。

---

# 4. 延迟优化

延迟来源包括模型排队、prefill、decode、检索、工具调用、网络、队列等待和多轮协作。

常见优化方式：

- 减少不必要的模型调用。
- 并行执行独立工具调用。
- 用小模型做快速路由。
- 对长上下文做摘要和裁剪。
- 使用 streaming 改善感知延迟。
- 将长任务异步化。
- 对慢工具设置超时和降级。
- 对常见请求缓存。

延迟优化要区分真实完成时间和用户感知时间。Streaming 可以改善感知，但如果最终任务很慢，仍然需要后台任务、进度提示和取消机制。

---

# 5. 限流、重试与熔断

可靠系统必须处理下游失败。

限流用于保护系统和控制成本。可以按用户、租户、接口、模型、工具和任务类型限流。

重试用于处理临时失败，例如网络抖动、模型服务 5xx、只读工具超时。重试要有指数退避和最大次数。

熔断用于防止故障扩散。当某个模型或工具连续失败时，系统暂时停止调用它，改走降级路径或返回明确错误。

需要注意，写操作不能随便重试。退款、发邮件、改数据库这类操作必须有幂等键和执行记录。

---

# 6. 降级策略

降级不是失败，而是用较低能力保证系统可用。

常见降级：

- 大模型不可用时改用小模型，并提示能力限制。
- RAG 服务不可用时只回答通用问题，拒绝需要最新知识的问题。
- 工具超时时返回当前已知状态和稍后通知。
- 多 Agent 深度流程失败时退回单 Agent 简化流程。
- 评审 Agent 不可用时进入人工审批。
- 超预算时返回部分结果和未完成项。

好的降级策略要诚实。不要在证据不足或工具失败时假装完成任务。

---

# 7. 扩缩容

Agent 系统通常有两类扩缩容：在线服务扩缩容和后台 Worker 扩缩容。

在线服务关注低延迟和稳定连接，尤其是 streaming 场景。后台 Worker 关注吞吐、队列积压和任务完成时间。

如果自托管模型，还要关注 GPU 扩缩容。GPU 容量比普通 CPU 服务更昂贵，启动更慢，也更需要 batching 和队列控制。

扩缩容指标包括：

- CPU/GPU 利用率。
- 队列长度和等待时间。
- P95/P99 延迟。
- 模型服务吞吐。
- 错误率和超时率。
- 单任务平均成本。

不要只按 CPU 扩容 Agent 服务，却忽略模型服务或外部工具的瓶颈。

---

# 8. SLA 与可靠性目标

Agent 系统也需要可靠性目标。

可以定义：

- 可用性：接口是否可用。
- 任务成功率：任务是否完成。
- 质量成功率：完成结果是否合格。
- 延迟目标：P95 响应时间或任务完成时间。
- 成本目标：单任务平均成本。
- 安全目标：越权拦截、注入防护、审批覆盖。

Agent 的 SLA 不应只看 HTTP 200。一个请求返回 200 但答非所问、越权调用工具或消耗巨大成本，都不是成功。
