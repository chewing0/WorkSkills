
> 目标：建立从“应用程序”到“硬件资源”的完整心智模型，能够解释操作系统的核心机制、分析常见性能问题，并清晰回答后端与基础架构岗位中的操作系统问题。

## 一、学习目标

完成本专题后，应当具备以下能力：

- 理解操作系统为什么需要进程、虚拟内存、文件系统等抽象。
- 说清楚程序从启动、运行、阻塞到退出的完整过程。
- 理解并发、同步、死锁、调度及其性能代价。
- 理解虚拟内存、页表、TLB、缺页异常和内存映射。
- 理解文件读写经过用户态、内核态、页缓存和存储设备的路径。
- 理解中断、系统调用、DMA、I/O 多路复用等机制。
- 理解虚拟机、Namespace、Cgroup 和容器隔离的基础原理。
- 能使用 Linux 工具观察 CPU、内存、磁盘、进程和系统调用。
- 面对实际问题时，能够按“现象 → 指标 → 定位 → 原理 → 解决方案”完成分析。

### 10. Linux 观测与性能分析

#### 核心内容

- USE 方法：Utilization、Saturation、Errors。
- CPU：使用率、负载、上下文切换、运行队列、软中断。
- 内存：RSS、VSS、Page Cache、Swap、Major/Minor Fault、OOM。
- 磁盘：IOPS、吞吐量、延迟、队列深度、使用率。
- 进程：文件描述符、线程状态、系统调用、锁等待。
- 常用工具：`top`、`ps`、`vmstat`、`pidstat`、`iostat`、`sar`、`strace`、`lsof`、`perf`。
- `/proc` 与 `/sys` 中的关键观测入口。
- 性能分析原则：先建立假设，再用指标证伪；先找瓶颈资源，再下钻调用路径。

#### 常见场景

- CPU 使用率高，但系统吞吐没有提升。
- Load Average 很高，但 CPU 使用率不高。
- 进程内存持续上涨或频繁 OOM。
- 磁盘延迟高，服务请求出现长尾。
- 线程数量异常、上下文切换激增。
- 文件描述符耗尽。
- 大量进程处于 D 状态或出现僵尸进程。

## 四、贯穿全程的三个视角

学习每一个机制时，都从下面三个视角组织笔记，避免只记结论。

### 1. 抽象视角

- 它向上层提供了什么抽象？
- 它隐藏了哪些硬件或实现细节？
- 它与相邻模块的边界在哪里？

### 2. 机制视角

- 核心数据结构是什么？
- 正常路径、阻塞路径和异常路径分别怎样执行？
- 资源在何时创建、引用、回收？

### 3. 权衡视角

- 它解决了什么问题，又带来了什么成本？
- 时间、空间、吞吐、延迟、公平性之间如何取舍？
- 在什么场景下应使用另一种方案？

## 六、学习方法

每个主题使用一个“小闭环”完成学习：

1. **预习**：先写出自己对核心问题的直觉答案。
2. **学习**：阅读教材或资料，画出关键执行流程。
3. **验证**：通过代码、命令或观测工具验证至少一个现象。
4. **输出**：不看资料，用自己的话写一页总结。
5. **复习**：分别在第 1、3、7、14、30 天进行主动回忆。

判断一个知识点是否真正掌握，不以“看懂”为标准，而以能否完成下面四件事为标准：

- 用一句话解释它解决的问题。
- 不看资料画出主要执行流程。
- 说明至少一个设计代价或适用边界。
- 用实验或系统指标验证一个相关现象。

## 八、综合项目建议

按难度从低到高选择，不要求一次全部完成：

1. **迷你 Shell**：实现命令执行、管道、重定向、后台任务和子进程回收。
2. **线程池**：实现任务队列、条件变量、优雅退出和压力测试。
3. **内存分配器**：实现简单的空闲链表，观察碎片与合并策略。
4. **并发 Key-Value Server**：使用 `epoll + 线程池`，分析锁竞争与 I/O 路径。
5. **用户态文件系统或简化文件系统模拟器**：理解目录、Inode 和块分配。
6. **简易容器**：组合 Namespace、Cgroup、Rootfs，理解容器启动过程。

每个项目至少保留以下产物：设计图、关键代码、实验数据、问题记录和复盘总结。

## 九、高频面试主线

优先保证下面这些问题可以从原理一路回答到工程影响：

## 十、推荐资料

### 主教材

- 《Operating Systems: Three Easy Pieces》：主线清晰，适合建立虚拟化、并发、持久化三大主题的框架。
- 《现代操作系统》：覆盖面完整，适合查缺补漏。
- 《深入理解计算机系统》：连接程序、编译、处理器、内存、链接和系统级 I/O。

### 实践与源码

- MIT 6.S081 / xv6：通过实验理解系统调用、页表、陷阱、锁和文件系统。
- Linux `man` 手册：确认系统调用、命令和内核接口的准确语义。
- Linux 内核源码与官方文档：在掌握概念后针对具体机制下钻，不建议一开始通读。

### 资料使用原则

- 选择一本主教材推进，其他资料只用于补充，避免在多个来源之间反复切换。
- 先掌握机制和流程，再阅读实现细节；先做可观测实验，再深入源码。
- 面试资料用于检查表达和遗漏，不能替代教材、实验与独立推导。
